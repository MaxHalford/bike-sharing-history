***📝 [See blog post](https://maxhalford.github.io/blog/bike-sharing-forecasting-training-set/)***

This repo tracks the status of physical docking stations from various bike-sharing providers. Dockless operators and virtual parking zones are out of scope. Most sources follow the [GBFS](https://github.com/MobilityData/gbfs) standard; Taiwan's systems use YouBike's first-party station feed. Some non-GBFS station data is provided by [CityBikes](https://citybik.es/). The data is fetched every 12 minutes. The results are stored and versioned as [GeoJSON](https://www.wikiwand.com/en/GeoJSON) files. This is done using the [git scraping](https://simonwillison.net/2020/Oct/9/git-scraping/) technique.

The weather forecast for the next 24 hours is collected hourly for each city.

Everyone is welcome to add new cities. You simply have to contribute the necessary details to [`scrape/systems.py`](scrape/systems.py), and then send out a pull request.

For a lightweight code checkout, clone only `main`:

```sh
git clone --single-branch --branch main https://github.com/MaxHalford/bike-sharing-history.git
```

A plain full clone asks git for every city-history branch and is intentionally much larger.

## Archives

The git history contains station snapshots collected approximately every 12 minutes and weather snapshots collected approximately hourly. Monthly Parquet exports are stored in public GCP buckets. Archives are rebuilt from actual file changes on every city branch and use one fixed, provider-neutral schema across all cities. Provider-specific fields are nullable when they have no meaningful equivalent.

> [!WARNING]
> Collection and archive generation are best-effort, so missing observations should not be interpreted as proof that a system was unavailable.

An easy way to query the station files is to use [DuckDB](https://duckdb.org/):

```py
import duckdb

with duckdb.connect(":memory:") as con:
    con.execute("SET TimeZone='UTC'")
    updates = con.execute("""
        SELECT *
        FROM read_parquet(
            'https://storage.googleapis.com/bike-sharing-history/toulouse/jcdecaux/*/*.parquet'
        )
    """).fetch_df()
```

Weather exports follow the same layout in the `weather-forecast-history` bucket:

```py
with duckdb.connect(":memory:") as con:
    con.execute("SET TimeZone='UTC'")
```

### Example: build a custom archive from git

It might be that the schema of the archives doesn't fully suit your application. The good news is that the git history is the source of truth. Indeed, you can build your own exports by looping through the git history of a particular city, and processing it however you want. Start by cloning only the city you need:

```sh
git clone \
  --single-branch \
  --branch city/mexico-city \
  https://github.com/MaxHalford/bike-sharing-history.git \
  bike-sharing-mexico-city
cd bike-sharing-mexico-city
```

The following self-contained example walks ECOBICI's August 2024 git history and writes a custom Parquet table. Save it as `export.py`; edit `FIELDS` or `station_to_row` for your research question. `UNTIL` is exclusive.

```py
import datetime as dt
import gzip
import json
import pathlib
import subprocess
import tempfile

import duckdb

SOURCE = "data/stations/mexico-city/ecobici.geojson"
METADATA = "data/scrapes/stations/mexico-city.json"
PROVIDER = "ecobici"
SINCE = dt.datetime(2024, 8, 1, tzinfo=dt.timezone.utc)
UNTIL = dt.datetime(2024, 9, 1, tzinfo=dt.timezone.utc)
OUTPUT = pathlib.Path("ecobici-2024-08.parquet")
FIELDS = [
    "station_id", "name", "short_name", "external_id", "capacity",
    "num_bikes_available", "num_bikes_disabled", "num_docks_available",
    "num_docks_disabled", "is_installed", "is_renting", "is_returning",
    "last_reported",
]


def git(*args):
    return subprocess.check_output(["git", *args], text=True)


def read_blob(process, name):
    process.stdin.write(f"{name}\n".encode())
    process.stdin.flush()
    header = process.stdout.readline().decode().split()
    if header[-1] == "missing":
        raise FileNotFoundError(name)
    content = process.stdout.read(int(header[2]))
    process.stdout.read(1)  # trailing newline
    return json.loads(content)


def station_to_row(feature, commit, committed_at_utc):
    properties = feature["properties"]
    longitude, latitude = feature["geometry"]["coordinates"][:2]
    row = {field: properties.get(field) for field in FIELDS}
    row.update({
        "city": "mexico-city",
        "provider": PROVIDER,
        "longitude": longitude,
        "latitude": latitude,
        "git_commit": commit,
        "committed_at_utc": committed_at_utc.isoformat(),
        "source_path": SOURCE,
    })
    return row


commits = git(
    "log", "--reverse", "--diff-filter=AMR", "--format=%H%x09%cI",
    f"--since={SINCE.isoformat()}", f"--until={UNTIL.isoformat()}",
    "--", SOURCE, METADATA,
).splitlines()

objects = subprocess.Popen(
    ["git", "cat-file", "--batch"], stdin=subprocess.PIPE, stdout=subprocess.PIPE
)
rows = 0
with tempfile.TemporaryDirectory() as temporary:
    ndjson = pathlib.Path(temporary) / "rows.ndjson.gz"
    with gzip.open(ndjson, "wt", encoding="utf-8", compresslevel=1) as output:
        for line in commits:
            commit, timestamp = line.split("\t")
            committed_at = dt.datetime.fromisoformat(timestamp).astimezone(dt.timezone.utc)
            if not SINCE <= committed_at < UNTIL:
                continue

            # Metadata exists only for new branch-native scrapes. It lets us
            # retain successful unchanged polls while excluding known failures.
            try:
                metadata = read_blob(objects, f"{commit}:{METADATA}")
            except FileNotFoundError:
                metadata = None
            if metadata:
                result = next(
                    (item for item in metadata["systems"]
                     if item["provider_slug"] == PROVIDER),
                    None,
                )
                if result and result["status"] != "ok":
                    continue

            try:
                snapshot = read_blob(objects, f"{commit}:{SOURCE}")
            except FileNotFoundError:
                continue
            for feature in snapshot["features"]:
                output.write(json.dumps(
                    station_to_row(feature, commit, committed_at),
                    ensure_ascii=False,
                ) + "\n")
                rows += 1

    objects.stdin.close()
    objects.wait()
    source = str(ndjson).replace("'", "''")
    destination = str(OUTPUT).replace("'", "''")
    duckdb.sql(f"""
        COPY (SELECT * FROM read_ndjson_auto(
            '{source}', union_by_name=true, sample_size=-1
        ))
        TO '{destination}' (FORMAT PARQUET, COMPRESSION ZSTD)
    """)

print(f"Wrote {rows:,} rows to {OUTPUT}")
```

Run it with `uv run --with 'duckdb>=1.4' export.py`.

Some details are important when interpreting the history:

- Station names are descriptive labels, not stable identifiers. Prefer the provider's `station_id` (or JCDecaux `number`) within each snapshot, while retaining `external_id`, `short_name`, `name`, and coordinates as time-varying attributes. Providers can still reassign identifiers, so long-running identity resolution should preserve the effective time of every mapping rather than assuming that any one field is permanent.
- In the legacy history, a missing file change is ambiguous: git cannot distinguish a failed fetch from a successful fetch whose output was identical. New scrapes record each system's result, retry count, and UTC request window under `data/scrapes/`; exports include successful unchanged polls and exclude recorded failures.
- New branch-native scrapes timestamp each city commit using that city's latest request-completion time. This avoids assigning every city the timestamp of one later, workflow-wide commit.
- GBFS `last_updated` cannot be recovered from the legacy history because the scraper stored the station arrays but discarded the feed-level metadata -- sorry for that. Station-level `last_reported` was retained. New snapshots preserve feed metadata too. For legacy data, `committed_at_utc` is the best available observation timestamp.
